# deploy/kubernetes/nas-csi

Static Kubernetes substrate manifests for the `nas-csi` driver.

`nas-csi.yaml` is the manifest reconciled by:

```sh
nas-csi-host-agent cluster apply --config /etc/nas-csi/host.yaml --execute
```

It contains only driver infrastructure: RBAC, `CSIDriver`, StorageClasses, the
controller Deployment, and the node DaemonSet. It intentionally does not create
application workloads or example PVCs.

The controller ConfigMap is deliberately host-neutral. It enables the durable
state file at `/var/lib/nas-csi/controller/state.json`, keeps dynamic dataset
creation disabled, and does not include a TrueNAS URL or API key path. A
host-local installer or operator config can add the `truenas` stanza when
controller-managed registration or dynamic dataset operations are intentionally
enabled.

Static existing-dataset PV/PVC objects are generated by the host-agent storage
installer, not committed in this directory:

```sh
nas-csi-host-agent csi install --config /etc/nas-csi/host.yaml --execute
```

That command also writes `/etc/nas-csi/node.yaml` inside each VM before the node
DaemonSet is expected to start, then runs smoke pods to verify staging,
publishing, restart behavior, fail-closed missing exports, read-only exports,
and host/pod directory visibility.

The driver images are pinned to the lab tags built by:

```sh
cargo run -p nas-csi-xtask -- build-images
```

Example PV/PVC files live under `examples/` and are for manual testing.
